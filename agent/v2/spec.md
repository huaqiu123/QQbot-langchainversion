# Agent V2 — RAG 知识库增强 Spec

## 背景

`agent/` 已实现基于 LangChain `create_agent` + DeepSeek 的联网问答后端（V1）。
当前 Agent 每次提问都走联网搜索，没有「记忆」—— 无法利用历史群聊消息或
已积累的知识来回答问题。

NapCat/OneBot 协议层尚未接入。V2 先补齐知识库能力，后续 NapCat 接入后
可将群聊消息持续写入知识库，实现「群聊记忆」。

## 目标

1. **知识库写入接口**：提供一个 HTTP 接口，调用方（如 NapCat）可将消息/文本片段
   写入知识库，同时存入向量库和关系库
2. **先查库再回答**：用户提问时，Agent 自动从知识库检索相关内容，注入 prompt
   作为上下文
3. **知识库足够则基于知识库回答**：检索到足够相关信息时，模型据此生成回答
4. **知识库不足则联网搜索**：知识库不足以回答时，模型自主调用 `web_search` 补充
5. **知识库持续积累**：调用方可随时写入新内容，写入后立即可被检索到，
   无需停机或执行额外维护操作

## 功能需求

### F1：知识库写入接口

提供一个 HTTP 接口 `POST /knowledge/ingest`，调用方可向知识库中写入文本内容。

- 请求体包含要写入的文本内容（必填）及可选的元数据（如来源群组 ID、发送者等）
- 写入的内容会被自动分块、向量化后存入知识库
- 写入成功后返回写入的文档块数量
- 鉴权与 V1 现有接口一致（共用 `X-API-Key`）

### F2：知识库检索状态接口

提供 `GET /knowledge/status`，查询知识库的当前状态。

- 返回知识库中的文档块总数、文本片段总数
- 用于监控和运维

### F3：知识库集成到问答流程

用户通过 `/v1/agent/ask` 或 `/v1/agent/stream` 提问时：

- Agent **自动检索**知识库，获取与问题最相关的前 K 条内容
- 将检索到的知识库内容注入系统提示词（prompt）作为上下文
- 模型**优先基于知识库内容**回答；知识库内容不足以回答时，模型自主调用
  `web_search` 联网补充
- 知识库检索结果为空时，完全退回 V1 的联网搜索流程

### F4：知识库持续积累

- 调用方可随时调用 `POST /knowledge/ingest` 追加写入新内容
- 写入后立即生效，新内容可被后续提问检索到
- 无需停机或执行额外维护操作

### F5：保留 V1 全部现有功能

- V1 现有的 4 个接口（`/`、`/health`、`/v1/agent/ask`、`/v1/agent/stream`）
  行为不变
- 未配置 Embedding API Key 时，知识库功能自动降级，Agent 退化为 V1 行为
- 现有配置项保持向后兼容

## 非功能需求

### N1：带病启动

- 未配置 Embedding API Key 时，知识库功能不可用，但 Agent 的 V1 联网问答能力
  不受影响
- `/health` 应反映知识库状态

### N2：向后兼容

- V1 的所有接口、请求格式、响应格式保持不变
- 现有 `.env` 配置项无需修改即可升级到 V2
- 新增配置项均有默认值，不填不影响服务启动

### N3：写入性能

- 单次 `/knowledge/ingest` 写入应在 2 秒内完成（假设单次写入文本长度不超过
  5000 字、网络正常）
- 写入不应阻塞问答接口的正常服务

### N4：检索精度

- 知识库检索使用相似度阈值机制，低于阈值的结果不注入 prompt，避免引入不相关
  信息干扰模型

## 不做的事

- 不提供知识库的手动编辑/删除接口 —— 仅支持追加写入
- 不提供文件上传/PDF 解析 —— 仅接收纯文本
- 不提供知识库的自动过期/清理机制
- 不做多租户/权限隔离 —— 整个进程共享一个知识库
- 不做 Embedding 模型微调
- 不安装本地 Embedding 模型（不引入 PyTorch / sentence-transformers）
- 不做 NapCat/OneBot 协议接入 —— 本轮只做 Agent V2 后端

## 验收标准

### AC1：知识库写入

- 调用 `POST /knowledge/ingest` 写入一条文本，能收到 `200` 响应且
  `chunks > 0`
- 写入成功后在服务端文件系统中可观察到 Chroma 持久化目录和 SQLite 文件已更新

### AC2：知识库写入鉴权

- 配置了 `AGENT_API_KEY` 后，不带 `X-API-Key` 头调用 `/knowledge/ingest`
  返回 `401`
- 带了错误 `X-API-Key` 返回 `401`
- 未配置 `AGENT_API_KEY` 时，无需鉴权即可写入

### AC3：知识库状态查询

- 写入前调用 `GET /knowledge/status`，返回 `chunk_count = 0`
- 写入一条文本后再次调用，`chunk_count > 0`

### AC4：知识库内容影响回答

- 先写入知识库：「DeepSeek-V3 于 2024 年 12 月发布」
- 然后提问：「DeepSeek-V3 什么时候发布的？」
- 回答应包含「2024 年 12 月」且不依赖联网搜索

### AC5：知识库不足时自动联网

- 知识库为空，提问一个时效性问题（如「今天有什么科技新闻？」）
- Agent 应调用 `web_search` 联网检索并给出回答

### AC6：V1 接口不变

- `/health` 返回 `status: ok`
- `/v1/agent/ask` 在知识库为空时行为与 V1 完全一致（仅联网搜索）
- V1 现有的所有配置项无需修改

### AC7：未配置 Embedding Key 时降级

- 清空 `.env` 中的 Embedding Key，重启服务
- `/health` 仍返回 `status: ok`
- `/v1/agent/ask` 仍可正常工作（退化为 V1 联网搜索）
- 调用 `/knowledge/ingest` 返回 `503` 并说明原因
